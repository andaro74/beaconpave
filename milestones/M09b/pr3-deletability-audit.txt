M09b PR 3 — deletability audit, at CHECK granularity
====================================================

Method, PR 2b's: mutate the PROPERTY a check protects and assert the mutation is live.
The old text must occur exactly once before the write, and the new text must be present
after it. Run the test file that owns the property and record what fires. Working
copies are backed up as bytes to a temp directory and restored FROM THERE, never with
`git checkout --`. Every restore is asserted byte-identical by SHA-256.

Two passes:

- PROPERTY (P1-P14, A1-A11, F1): the plant, run against the test file that owns the
  property. A red there makes the gate red. Failing cases are named.
- GATE (P1, P2): the two plants that measure whether rule gap 4 and the walker can land
  apart, each run through the GATE itself — `python -m pave.cli check`, not pytest. They
  are the plants this PR's scope rests on.

Plants that change the candidate record (A5, A6) re-pin its digest in the record AND in
`tests/test_m09b_admission.py`, so the digest check is not the door they go through
(one door per plant). A1 is the digest door itself.

Harness: a scratchpad script, not committed. Every mutation is quoted below.

Tree: the head of branch m09b-pr3-one-candidate-per-topic after its fifth commit
(subject: "the decoded-or-raw trigger re-dated to before the run, with the count its
reason rests on"). The P11 re-run and the gate pass ran after its sixth (subject: "the
docstring plant the audit found silent, and the walker finding for the additive topic").

GATE PASS — is rule gap 4 separable from the walker?
----------------------------------------------------

  P1   widened home, walker removed        gate exit 1 (red)             CAUGHT
  P2   walker kept, home not widened       gate exit 1 (red)             CAUGHT

Each ran the whole gate over the planted tree. The harness's pytest-summary parser named
no failing case from the gate's output format, so the property pass names the cases;
the gate pass records only that the gate went red. Both restores byte-identical.

Read together with the property pass: with the home widened and no walker (P1), a
guardrail control on the stack file reads WALKED at exit 0 whatever its selector names,
which test_a_guardrail_control_is_never_walked and test_a_two_control_disposition_resolves
refuse. With the walker and no widened home (P2), the stack file is refused before any
walk starts. Neither half lands alone without taking the gate red, so rule gap 4 and the
walker are NOT separable, which is why they are one commit.
