M09b PR 1d — deletability audit for the replacement spec and the admission rule
================================================================================

Method: mutate the thing the PR adds, assert the mutation is LIVE in the file, run
the check, record whether anything fires. Working copies backed up to a temp
directory and restored FROM THERE, never `git checkout --` (which would delete the
uncommitted change the audit exists to test). Bytes read and written as bytes, so
no line ending is flipped: `git diff --stat` after the audit shows only the lines
this PR adds.

The audit runs the GATE for every plant expected to be silent — `make check`, not
`pytest tests/` — which is M09's own open debt fired at every PR. Two plants
expected to be caught were run against the file that catches them, because a red
there makes the gate red and a 167-second run adds nothing to that fact; the
verdict claimed for them is CAUGHT and the failing case is named.

Baseline on the tree the plants ran against: 4494 passed, 8 skipped, `make check` PASS.
That tree is this PR's diff without `docs/pr-bodies/m09b-pr1d.md`, which had not been
written yet; the complete diff measures 4499 passed, 8 skipped. Both counts are stated
with the tree they were measured on, and no delta arithmetic is published for either —
which is this PR's own correction to PR 1c's body, in `milestones/M09b/journal-notes.md`.

This PR adds documents, one ADR index row, one YAML declaration and one journal
note. It adds no test and no assertion, so the audit is over the things a READER
depends on rather than over new checks. Five were mutated. Every one.

What this audit does not claim
-------------------------------
It does not claim the admission rule is right, that the licence read from each
corpus is the licence that file actually grants, or that ten axes are the ten a
seat would name. Nothing in this repository can assert those. They rest on the
seats, on the next cold review, and on PR 3's two rounds being told what to plant
rather than what to read.

It also does not claim these five are all the things a reader depends on in this
diff. Three prose corrections — `README.md`'s footnote, `SPEC/README.md`'s row and
`BUILD.md`'s row — were rewritten off the withdrawn rule's language and are
unchecked by construction, which is the standing debt that no spec and no ADR is
on any two-key rule and that prose is held by nothing but a reader.

Summary: 2 CAUGHT, 3 SILENT. Two of the three silences carry a debt with an owner
and a trigger; the third is attached to a debt that already exists. No test was
written to its own data to turn a silence green.
